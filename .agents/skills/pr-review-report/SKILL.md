# PR Review Report

任意のGitHub PRを、レビュアーが素早く把握できるインタラクティブHTMLレポートに変換して
Artifactとして公開するスキル。3タブ構成（変更ファイル / AIレビュー / 変更の要約）。

**必ず `template.html`（このSKILL.mdと同じディレクトリ）をコピーして出発点にする。
CSS/JSをゼロから書き直さない。** テンプレートには過去に実際にハマった罠（下記
「既知の罠」参照）の修正が反映済み。書き直すと同じ罠を再現する。

## 0. 前提確認（曖昧なら AskUserQuestion で聞く）

- 対象は「今いるブランチのPR」か「PR番号/URL指定」か。
- AIレビュー（Codex/別のレビューツール等）を実施済みか、これから実施するか、
  今回は省略するか。→ 省略する場合はタブ2を丸ごと削除する（手順4参照）。
- 対象リポジトリに既存のデザイントークン/テーマファイルがあるか（`theme.dart`,
  `tailwind.config`, `tokens.json` 等）。あれば流用する（手順2参照）。

## 1. データ収集

```bash
# ベースブランチとの差分統計
git diff --stat <base>..<head>
git diff --numstat <base>..<head>   # ファイルごとの +/- 生数値（グラフの元データ）

# コミット履歴（要約タブのアーク分割・タイムライン軸に使う）
git log --reverse --format='%h|%ad|%s' --date=format:'%Y-%m-%d %H:%M' <base>..<head>

# CI状態（誠実に。未確認なら appbar の "✓ 全チェック成功" チップを出さない）
gh run list --branch <branch> --json databaseId,status,conclusion,name,headSha
gh pr view <number> --json title,number,headRefName,baseRefName,url
```

AIレビューを実施する場合は既存のレビューツール（`codex review` 等、プロジェクトの
CLAUDE.mdやメモリに記載があれば従う）を使い、指摘は**必ず自分でも実コードを読んで
独立検証**してから掲載する。ツールの言い分をそのまま貼らない。

## 2. デザイン方針

- 対象リポジトリに既存のデザイントークン/テーマがあれば、`template.html` の
  `:root` / `@media (prefers-color-scheme: dark)` / `[data-theme]` 3箇所の
  色変数を丸ごとそちらの値に差し替える（light/dark両方揃っているトークンでなければ
  ダークは自分で妥当な値を補う）。
- なければテンプレートのデフォルト（Material 3 Baseline, seed #6750A4）をそのまま使う。
  勝手に別の配色を発明しない。
- diffの `--diff-add-*` / `--diff-del-*` はブランドaccentと独立の意味色。
  テーマを差し替えてもこの2色は基本そのままでよい（プロジェクトに合わせて
  トーンだけ微調整する程度）。

## 3. データ→テンプレートの埋め方

### 変更ファイルタブのドーナツ/ファイルグループ
- ファイルをディレクトリ単位で**3グループ以内**に集約する（多いと意味を失う）。
  近い関心事はまとめる（例: CI設定ファイル + ビルドスクリプト → 「CI & tooling」）。
- 各グループの合計行数（insertions+deletions）から角度を計算:
  `deg = group_lines / total_lines * 360`。3グループの角度は必ず合計360°。
- 各ファイル行の bar 幅%は「そのグループ内での最大変更行数」を100%として比率計算。
- ファイル一覧はグループ内で変更行数の降順に並べる。

### コミットタイムライン軸
- `left% = (commit_time - first_commit_time) / (last_commit_time - first_commit_time) * 100`
- `animation-delay` は時系列順に少しずつ増やす（50ms刻み程度）と発生順のアニメーションになる。
- ドット色は commit prefix（feat/fix/chore）に対応させる。当てはまらない接頭辞は
  最も近い意味のクラスに丸める。

### AIレビュータブ
- 指摘ごとに `finding` を1つ。修正済みなら実際の diff（before/after）を
  `diff-line add/del/ctx` で構成。見送りなら `diff-line note` で該当箇所を
  指し示すだけにする（架空の diff を書かない）。
- `finding__verify` は**実際に手元で再現/確認した場合のみ**書く。していないなら
  要素自体を削除する（やっていないことをやったように書かない）。
- ステータスバー（修正済み/見送りの割合）は実際の件数から計算する。

### 変更の要約タブ
- コミットをテーマ・時間的なまとまりで「アーク」に分割する（1アーク=1つの作業の弧）。
  細かすぎず、かつ全部を1つに潰さない。目安2〜5アーク。
- 各アークに、最も技術的に特徴的な diff スニペットを1〜2個添える
  （全差分を貼らない。読み手が「何が起きたか」を掴める最小限を選ぶ）。

## 4. AIレビューを実施しない場合

- `tabbar` から `#tab-review` ボタンを削除。
- `main` から `#panel-review` セクションを削除。
- JSの `panels` オブジェクトから `'panel-review'` の行を削除。
- タブ構成が2つになるので `.tab-indicator` の初期化ロジックはそのままで動く
  （動的にDOM要素から幅を計算しているため、タブ数に依存しない）。

## 5. 既知の罠（テンプレートには修正済みだが、手を入れる際は再発させない）

1. **折りたたみ(grid-template-rows: 1fr→0fr)の要素に padding/border を直接置かない。**
   border-boxでもpadding分は物理的に残って0まで潰れない。paddingは潰れる要素の
   もう1段内側の子（`.fb-pad` 相当）に置く。
2. **ファイルパスの省略方向を逆にしない。** 省略していいのはディレクトリ部分
   (`.dir`: flex-shrink:1 + ellipsis)。ファイル名 (`.base`) は常に
   flex-shrink:0 でフルテキストを保持する。
3. **チェックトグルボタンは折りたたまれる領域の外に置く。** 折りたたみ対象
   (`finding__body` / `arc__collapsible`) の中に置くと、チェックした瞬間に
   ボタン自体が隠れて二度と開けなくなる。
4. **タブラベルに `white-space: nowrap` + `flex-shrink: 0`、タブバーに
   `overflow-x: auto` を付ける。** 付けないとモバイル幅でラベルが単語の途中で
   折り返れて崩れる。
5. **カスタムチェックボックス/スイッチの `<input>` は視覚的に隠れている。**
   Playwrightで自動操作する際は `<input>` ではなく `<label>` や `.track` を
   クリックする。
6. **`localStorage` は初回読み込み時に一度だけ読まれ、メモリ上の変数に
   保持される。** テスト中に `localStorage.clear()` しても、そのタブの
   JS変数は更新されない。クリア後は必ず `location.reload()` してから
   状態を確認する。
7. **STORAGE_KEY はレポートごとに一意にする**（org/repo/PR番号を含める）。
   Artifactは同一オリジンでホストされるため、複数PRのレポートを同じ
   ブラウザで開くとキーが同じだとチェック状態が混線する。
8. **`<meta charset="utf-8">` を明示する。** 無いとローカルの簡易HTTPサーバ
   経由でのプレビュー時に日本語タイトルが文字化けすることがある
   （Artifact公開後は自動付与されるが、ローカル動作確認のために書いておく）。

## 6. 検証（公開前に必ず実施）

Playwright MCP でローカルサーバ経由で確認する（`python3 -m http.server` 等）。

- [ ] 3タブすべて切り替わり、インジケータが正しい位置に動く
- [ ] ドーナツの数字カウントアップ、ファイル行のバー、ステータスバーが
      スクロールで正しくアニメーションする
- [ ] AIレビュー/要約タブの `check-toggle` をクリック → 折りたたまれる →
      再読み込み後も状態が保持される（`localStorage.clear()` → `reload()` →
      クリック → `reload()` の順で確認する）
- [ ] 「確認済みを非表示」スイッチでチェック済み項目が隠れる
- [ ] ファイルパスが長いファイルで、ファイル名が省略されず全部見えている
- [ ] ダークモード（`document.documentElement.setAttribute('data-theme','dark')`
      で確認）で配色が破綻していない
- [ ] モバイル幅（390px）でタブラベルが崩れない、diffブロックだけが横スクロール
      してbody自体は横スクロールしない
- [ ] コンソールエラーが0件

確認用に作成したスクリーンショット等の一時ファイルは、公開前に削除する
（対象リポジトリの `git status` に残さない）。

## 7. 公開

`Artifact` ツールで公開する。`favicon` は絵文字1〜2個、`title`/`description` は
具体的に（PR番号とテーマが分かるように）。同じPRのレポートを更新する場合は
同じファイルパスで再公開すればURLは変わらない。
